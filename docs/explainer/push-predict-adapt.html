This is a browser simulation that explains the idea. It is not a result. Here a small Bayesian model stands in for TabPFN: it learns from the table how far and in which direction an object slides, with a spread. The real project calls TabPFN-3.5 on MuJoCo rollouts, where the table can also hold contacts, orientation and object features, and TabPFN learns the shape of the relationship itself.

How one decision works

Predict, plan, act, learn. The table is the memory.

1 · Predict

TabPFN reads the table

Context rows are past pushes: where the object was, how it was pushed, where it went. For each of 136 candidate pushes, TabPFN predicts where the object will land, as a distribution, not one point.

2 · Plan

Pick the safest good push

Score each candidate by expected distance to the target plus its spread. Reject any push whose 95% landing zone leaves the table. When unsure, a short push wins.

3 · Act

The arm pushes

One push in MuJoCo, or on a real arm. The object slides with whatever physics it really has: heavier, slipperier, lopsided.

4 · Learn

Add one row

The real outcome becomes a new row in the table. That is the whole learning step. No gradient, no retraining, about a second per decision.

Why RL fails at this exact moment

RL learns a reflex. We learn a model, live.

An RL policy maps situation to action. It was optimised for the physics it trained on, so when the object changes, it keeps making the same move. On the ice puck that means pushing far too hard, again and again. It has no step where today's evidence can change tomorrow's action.

Fair to say: meta-RL and online system identification can also adapt. They need a training pipeline built for that purpose. TabPFN brings in-context adaptation from its pre-training, and we compare against domain-randomised RL so the comparison is honest.

Where this matters outside the hackathon

Real robots meet new physics every day

Warehouses and parcel handling

Every parcel is a new object: different weight, contents, cardboard friction. A robot that sorts or nudges parcels has to adapt per item, with seconds, not hours, to learn.

parcel_id · x · y · aim · force → dx · dy

Home and service robots

Mugs, bottles, toys, on wood, glass or tablecloth. Nobody can simulate every kitchen. A few pushes in the real home are the training data.

object · surface · aim · force → slide distance

Wear and damage

A gripper pad wears out, a motor weakens, a wheel starts slipping. Same robot, new physics. Today's rows overrule assumptions from training without anyone retraining the robot.

command · joint state → actual motion

Field robots

Rovers and farm robots on mud, sand or wet grass: the same command moves them a different distance. They need a calibrated "how far will this take me" before committing.

terrain features · command → displacement ± spread

What these cases share

The physics changes after the robot is deployed. Data is scarce, because every real try costs time and risk. And the robot has to know when it is unsure. That combination is where an in-context model with calibrated uncertainty beats a trained policy, and it is exactly Prior Labs' brief: where things are, where they are going, what happens next.

What we have to prove by Sunday 16:30

Claims we will measure, not assume

Hypotheses

  • On objects it has never seen, TabPFN reaches the target in fewer pushes than RL.
  • Its 90% prediction bands contain about 90% of real outcomes (calibrated).
  • Uncertainty-aware planning drops fewer objects off the table.

Baselines

  • PPO trained on the wooden block
  • Domain-randomised PPO (the strong one), trained fast in JAX/MJX
  • MLP-ensemble world model given the same rows

Tests and risks

  • Held-out objects, hundreds of seeded episodes, confidence intervals
  • Latency per decision with a cached context and batched candidates
  • Risk: push physics in MuJoCo is noisy, so we measure that noise first
