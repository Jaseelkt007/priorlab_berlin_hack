Can a table fly a fruit fly?

TabPFN learns from a table of simulated fly flight, with no training. It predicts where the fly goes better than trained models. Flying the fly itself breaks down, and we have traced it to the wing actions.

Methodology

Seven experiments, from prediction to full control

Every experiment holds out the same 27 flight pairs (a flight and its mirror image stay on the same side), about 20% of each flight type, so nothing from a test flight reaches the context.

Constraints

What limited us, and how we worked around it

GPU memory3 GB
The GTX 1050 fits only 256 context steps; 512 runs out of memory.A Nebius H100 (80 GB) for the big-context sweep.
Loop rate0.2 ms
The fly needs a decision every 0.2 ms; TabPFN takes 97–270 ms.The simulator waits; we measure decision quality, not real time.
API limits~60 / min
The cloud API allows about 60 predictions a minute and about 5M tokens a day.The API is used only for offline A–C, with results cached; control runs locally.
Data coverage1.7 mm
99% of recorded steps stay within 1.7 mm of the ghost, so the context never shows a recovery.New strong-noise pass 6, drifting up to 11 mm.
Time~29 h
Hacking started Sat 11:00; the hard deadline is Sun 16:30.Quick fixes are logged in DEBT.md; the demo path is proven first.
Public repono secrets
The repo goes public at submission; data and model weights have their own licences.The token lives in a git-ignored .env; data and third-party code are git-ignored.
